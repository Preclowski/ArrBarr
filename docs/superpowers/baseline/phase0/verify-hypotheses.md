## Additional load-bearing facts

1. **`URLSession.shared` is load-bearing for the test suite.** `HTTPClient.swift:143-155` deliberately replaces `URLCache.shared` instead of giving clients a private session, because "a custom session ignores `URLProtocol.registerClass`, which is how the tool-backend tests stub their HTTP." A rewrite that moves to per-client `URLSession`s silently breaks ~14 stub-based test files unless they switch to `configuration.protocolClasses` at the same time.
2. **`ConfigStore` mutates process-global state.** `applyLanguage` writes `AppleLanguages` into `UserDefaults.standard` (`ConfigStore.swift:228-233`), and `resolveDefaults()` migrates `.standard` → group suite on first non-extension launch (`:291`). The config layer is not a pure data source.
3. **Two untyped-JSON read-modify-write paths exist** and are invisible to a compiler-driven rename: `ArrAPIClient.getJSONObject` (`:178-185`) and `SonarrClient.setSeasonMonitoredV3`'s deliberate double-PUT (writes the *opposite* value first to force Sonarr's episode cascade). Any new transport must preserve the double-PUT semantics or "grab S4" regresses.
4. **`ServiceConfig` carries `password` as well as `apiKey`** (`WidgetDataStore.serviceConfig` reads both) — download clients authenticate by username/password, not key, so an "API key" abstraction in a new comm layer is insufficient.
5. **Whisparr/qBittorrent/Transmission have live version-sniffing branches** encoded as comments+code (qBittorrent 5.2 changed the add-response shape and renamed `paused`→`stopped`; both spellings are sent unconditionally, `QbittorrentClient.swift:99-109`). A rewrite that "cleans up" the dual spelling breaks 4.x or 5.x.
6. **Transmission needs a header-level retry** (`X-Transmission-Session-Id` 409 handshake, `TransmissionClient.swift:171-211`) that the generic `HTTPClient.perform` cannot express — it reaches around the abstraction. Any new transport needs a response-header-visible escape hatch.
7. **`qBittorrent`/`Deluge` require their own cookie jar** (`HTTPClient.uncachedConfiguration()` at `:159-165`), i.e. the session is not uniform across clients.
8. **`URLSession` cancellation semantics are explicitly special-cased** (`HTTPClient.swift:262-269`): `CancellationError` and `URLError.cancelled` are rethrown bare, not wrapped as transport errors. Pull-to-refresh and overlapping refreshes depend on this.
9. **Poster fetching is a second, parallel HTTP stack** (`PosterStore.swift:374-396` builds its own `URLRequest`s with `X-Api-Key` and its own signposts) and does not go through `HTTPClient`. Two transports, not one.
10. **Realtime and polling are coupled through a floor**: `realtimeRefreshFloor()` (`QueueViewModel.swift:551-553`) mixes `backgroundInterval` into the SignalR-driven refresh rate, and `realtimeSilenceTimeout = 300` (`ConfigStore.swift:93`) decides when polling takes over. The cadence is not a single knob.
11. **`ArrBarr.entitlements` (OSS macOS) has no application-groups**, yet `resolveDefaults()` still returns the group suite and `WidgetDataStore` still probes the group container. The comment at `WidgetDataStore.swift:22-31` documents that `containerURL` returns a path there and `createDirectory` *succeeds* while writes are denied — a trap any new storage layer will re-walk.
12. **Plaintext secrets are on disk in the OSS build** (group-suite plist, `ArrBarr.secret.*` keys) as a direct consequence of H18. If the comm rewrite changes signing, key storage silently migrates — and `recoverSecretsFromKeychainIfNeeded` (`ConfigStore.swift:417-435`) exists precisely to paper over that transition.
13. **MediaKit has no queue/download/write surface at all** — 18 files, GET-only, Sonarr/Radarr/TMDB/media-server *read* providers. It is not a drop-in replacement for ArrCore's clients; it covers maybe a quarter of the operations counted in H6, and none of the six download clients.
14. **`CoalescingCache` has no TTL** (see H8) — a stale entry for a repointed server is only evicted by `identityFingerprint` being part of the key, which is the key-length fingerprint from H9. Those two facts compose into a real bug class: rotate a key to the same length and the resolver serves the old server's answers forever.

## Open questions for the owner

1. Is `xcode-select` intentionally pointed at CommandLineTools? Every build/test instruction in CLAUDE.md fails as written without `DEVELOPER_DIR`.
2. Should the comm rewrite target `MediaKit` (GET-only, v6 mode, macOS 14 floor) or a new package? MediaKit today has no write path, no download-client concept, no ProviderHealth implementation, and one unused protocol — adopting it means designing roughly 70% of the surface from scratch.
3. Is `identityFingerprint` using `apiKey.count` a deliberate "don't hash secrets" choice? A salted hash would fix the rotation blind spot without logging the key.
4. Do you want per-request instrumentation (signpost + `.notice` on failure) added to the new transport? Today nothing lets you count requests per screen (H19), which makes "the rewrite reduced traffic" unverifiable.
5. Should `Whisparr v2` remain supported? The client is pinned to `/api/v3` while `ArrDownloadClients` and demo fixtures still carry v2 shapes.
6. `URLProtocol`-based stubbing constrains the design (H6/fact 1). Is moving tests to injected sessions/protocol-level fakes in scope for the rewrite, or must `URLSession.shared` survive?
7. The 158 Codable types are the real migration cost. Is re-deriving wire models in the new layer acceptable, or must ArrCore's model types stay source-stable for the Views?
